# 两个独立产品

2026-09-28 从共同历史提交 `4ae4901` 开始拆分。两个仓库都保留此前 Git 历史，未重写远程历史。

| 仓库 | 产品内容 | Godot 名称 / 用户目录 | 启动场景 |
| --- | --- | --- | --- |
| [Block-Conquest](https://github.com/wanheng20031114/Block-Conquest) | 积木战争、四位指挥官、六图据点争夺 | 积木战争 | scenes/lobby.tscn |
| [Block-RTS](https://github.com/wanheng20031114/Block-RTS) | 传统 RTS、联机、肉鸽、沙盘、MOBA、图鉴 | Block-RTS | scenes/lobby.tscn |

两边均能单独克隆、导入和导出，不需要另一仓库、符号链接或 Git 子模块。首页、Session、设置、导出名称、测试与工具已各自独立。积木战争不包含 RelayClient、网络协议、传统 RTS 单位/经济系统或 RogueSession。

共同字体、菜单 Tween、转场、相机、音效池与少量音效在需要的一侧保留独立副本。Block-RTS 的菜单提示音位于 assets/audio/ui/，草地 shader 的共享片段位于 assets/models/environment/。积木战争民兵的原始网格输入已复制到自身模型目录。

首次启动积木战争只继承旧“积木争霸”的通用设置；Block-RTS 继承旧设置、大厅偏好和肉鸽存档。迁移只复制不存在的目标文件，不更改旧文件，不迁移日志或联机凭据。此后各自保存，互不覆盖。

拆分前的历史版本和性能报告保留其原始名称、数值与日期。原“积木争霸”的历史发布包不代表新产品的发布版本。Block-RTS 保持已有网络协议和线上中继的端口、TLS 身份，拆分本身不部署或修改线上服务。

原工作区中 assets/environment_obstacles.json 的未提交修改迁入 Block-RTS，保持未提交；用户已删除的预览 HTML 和 artifacts 忽略文件状态也被保留。忽略的本地缓存、验证产物、虚拟环境和部署凭据不进入新远程仓库。

两份项目均从没有 .godot 缓存的工作树导入。独立资源检查分别覆盖 167 / 580 个运行时文本资源，无跨产品依赖或缺失静态引用。

| 积木战争 | 首页、设置迁移、菜单动效、选择到战斗往返 | 377 项通过 |
| 积木战争 | 基础战斗、六图完整路由与选图、气势 AI、兔子技能、音效/音乐、2v2 与 3v3 完整 AI 对局 | 5,789 项通过 |

两边 Windows EXE、PCK 和 ZIP 均已构建。Block-RTS 的网络指纹保持 `d1e4c297d057036ae1c8dae31966cd646fcd2f2960519cf10d54b6453931f390`，没有改变线上协议或部署服务。两个首页与积木战争设置经过原生 Forward+ 渲染检查。

导出验证发现并修复了菜单已摘离场景树后，延迟入场回调仍访问 SceneTree 的问题。仅用于离线肖像制作的 portrait_studio 场景和原始网格输入从积木战争发布包排除，开发源文件仍保留。
